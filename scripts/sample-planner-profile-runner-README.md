## Boundaries, resource retention and process ownership

Each arm launches one fresh PHP process for cold/warmup/warm. Per-worker deadline30s; whole batch deadline600s, with5s reserved before each batch endpoint for cleanup. Output is captured as raw stdout.raw/stderr.raw plus command/process/result/validation JSON. Both stream EOFs must be observed with no cap truncation before output_completeness_unknown can be false. Timeout/cancellation/observer/capture/cleanup paths that lack either EOF retain output_completeness_unknown true; no post-termination drain or full-output claim is made on those paths. Per-stream capture is bounded8MiB; exceeding it terminates the observation, retains a labeled prefix/observed byte count and invalidates the pair. Result JSON is bounded8MiB. No worker exit code alone establishes validity. JSON duplicate keys are rejected.

The Linux runner installs SIGTERM/SIGINT handlers that only mark cancellation, checks cancellation while capturing/waiting/scheduling, and always runs worker finally cleanup before stopping new work. It enables/confirms child-subreaper status before spawning and requires pidfd APIs and readable /proc. It starts a new process session and retains a leader pidfd immediately after Popen returns, before inventory. It always cleans up after success/failure/timeout, retaining known owned child handles with checked /proc start identity. It reaps children and requires kernel ECHILD plus an empty owned descendant tree and empty original process group/session. Popen exceptions with no process object still undergo /proc descendant inspection and kernel ECHILD checks; they are never assumed closed. On inventory/deadline failure, finally still signals the leader/known-child handles and attempts nonblocking reaping, then explicitly reports closure UNPROVEN and aborts. Undiscovered descendants cannot be claimed gone merely because known handles were signaled. Escaped sessions remain descendants or reparent to the subreaper. Cleanup failure stops the batch; it never proceeds on unproven closure. /proc inventory/permission/identity/deadline failures also fail closed. Unexpected descendants on successful exit are killed, recorded and invalidate that observation even when closure subsequently succeeds.

Resource snapshots preserve raw cgroup CPU/memory fields and cumulative child rusage before/after each worker. These encompass startup, observer serialization and cleanup and are not exact caller resource intervals. Driver's caller timing/phase CPU context is retained separately. Process elapsed includes cleanup. Process stdout/stderr cap failures, result validation failures and missing artifacts remain visible. Invalid pairs never supply a valid attribution conclusion; the other arm may still be observed, but neither is rerun. Batch deadline retains scheduled-but-unstarted arms as invalid where reached; summary reports pairs not recorded after a fatal abort separately.
