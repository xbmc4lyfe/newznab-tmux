How to read the evidence

Every claim needs an identity, a boundary, and a limit.

Keep evidence states separate

StateWhat it establishesWhat it doesn't establish
Source inspectionThe behavior implemented at a named revision.Successful execution or production behavior.
Correctness testThe tested inputs met their assertions.Performance, complete input coverage, or deployment.
Paired benchmarkA comparison within a defined fixture and measured boundary.Whole-system throughput or a different machine's result.
Diagnostic profileWhere an instrumented workload spent time.An uninstrumented speedup against another implementation.
Merged pull requestThe fork accepted a specific source change.That a running installation uses it.
Healthy deploymentServices passed their deployment health checks.That a newly admitted release completed verification and publication.
Live publicationA fresh candidate produced persisted release/NZB evidence in the observed installation.A universal success rate or performance claim.

Record both source and executed revisions

A pull request's head can differ from the synthetic merge checkout that Actions executes. The frozen decoder reports come from PR head dc74ec057ebdd80a3ff7d10cbcf12147c06cf55d and executed merge 35c5a5a1bf1f8bd98a4e3f6f62ff4fa0f6eb4c04. The x86 provenance and ARM provenance retain those identities.

The newer retained PHP and presentation summaries are historical PR evidence. The API head is 35858d906f135266be148f5b20417ff73041f54c, executed merge 57dfddcfd029b361e92c4d6ddae21b200b57323b. Neither becomes a current-master result when documentation changes.

Current build publication

One Pages workflow combines the documentation, current summaries, and frozen reports. Every master push starts fresh benchmark workflows. Workflow start and completion events refresh the current dashboard. Collection checks repository, branch, source revision, architecture, run ID, and attempt. A newer attempt's failure must not fall back to an older attempt's pass.

The publisher accepts bounded public summaries, not arbitrary build directories. Raw fixture payloads, private configuration, binaries, and unrestricted logs don't belong on the site. Current, historical, and unavailable evidence use separate labels.

Ratios, intervals, and missing results

For latency, speedup equals baseline time divided by candidate time. For throughput, it equals candidate throughput divided by baseline throughput. A 2× latency speedup means half the time, or a 50% reduction. It doesn't mean a 200% reduction.

A confidence interval describes uncertainty under the experiment's method. A useful-improvement decision follows that harness's threshold. It isn't a general approval. An inconclusive comparison supports neither a reliable gain nor a reliable regression under that rule. A missing artifact, skipped workload, setup failure, invalid pair, or timeout is unavailable or invalid evidence, never zero latency.

The performance guide distinguishes median screens from the project's common-path and uncommon-p99 adoption requirement. The historical ingestion studies under performance evidence compare PHP/SQL storage changes. They're not PHP-to-Rust measurements.

Maintain the documentation

The prose uses the vendored Google style for Vale, version 0.7.1, with its MIT license. Run the following commands from an isolated repository checkout:

vale --config=github-pages/docs/.vale.ini github-pages/docs/content
python3 tests/Unit/test_docs_site.py
python3 tests/Unit/test_benchmark_pages.py
python3 tests/Unit/test_benchmark_summary_export.py
preview_dir="$(mktemp -d "${TMPDIR:-/tmp}/nntmux-docs.XXXXXX")"
bash github-pages/deployment/prepare-benchmarks.sh "$preview_dir"
echo '{"status":"unavailable","reason":"Offline preview has no current-build collection"}' > "$preview_dir/results.json"
python3 scripts/build-docs.py --output "$preview_dir"
python3 scripts/check-docs.py --site "$preview_dir"

Review source links and PR associations when updating a page. Preserve historical numbers with their original protocol and revision, and update the current dashboard through its collector. Don't rewrite a historical report to make it look current. New Rust files must appear in the coverage inventory even before a benchmark exists.

Scope of this site

This site documents a personal fork under development and testing. It doesn't certify production readiness or compare the quality of this project with upstream NNTmux. The upstream maintainers and contributors deserve credit for the main app and the foundation these experiments use.
